SysForge

دليلك السريع للتعامل مع منظومة بناء أنظمة SaaS الاحترافية. اضغط على أي أمر لنسخه.

⚡ الأوامر الأساسية

/sysforge [اسم النظام]

يبدأ مشروع جديد بالكامل ويشغل الـ Runtime Engine لبدء المراحل الـ 10.

/sysforge resume

يستأنف العمل في مشروع موجود بناءً على ذاكرة المشروع (project/context).

/sysforge status

يعرض الحالة الحالية للـ State Machine والمرحلة والتقييمات المعمارية.

/sysforge scope

لتعديل أو توسيع نطاق المشروع بعد بدايته (يتم توثيقه في الذاكرة).

🔄 دورة الآلة (State Machine)

النظام لا يكتب كوداً بشكل عشوائي، بل يمر عبر هذه الحالات الصارمة. لا يمكنك تخطي أي حالة.

PENDING → ACTIVE → VALIDATING

إذا نجح التقييم:

LOCKED (بانتظار موافقتك) → APPROVED → COMPLETED

إذا فشل التقييم:

FAILED (عزل وتوليد الجزء المعطوب فقط) → ACTIVE

🗺️ الخريطة (أهم المحطات)

4.5

SysArch (المعمارية)

تصميم الـ Domain Model وتحديد استراتيجية الـ Multi-tenant والصلاحيات. ممنوع كتابة أي كود هنا. يتوقف النظام بعدها لأخذ موافقتك الصريحة.

5

Devil (الهجوم المعماري)

نظام داخلي يهاجم الخطة للبحث عن الثغرات (SPOF، مشاكل التوسع، تسريب بيانات الـ AI) قبل كتابة الكود.

7A

SysCore (الأساس)

بناء الطبقات الـ 6 الأساسية (قاعدة البيانات، RLS، المصادقة بـ HttpOnly، صلاحيات RBAC).

7B

SysWeb (المميزات)

بناء وحدات النظام بشكل متكرر. يفرض قاعدة "3 ملفات لكل Feature" ويمنع تماماً الـ Spaghetti Code.

🛡️ قواعد التعامل مع النظام

  • لا تجبره على تجاوز المراحل: لا تطلب منه كتابة صفحة الـ UI قبل أن يعتمد لك الـ Architecture.
  • أجب على أسئلة الـ Gates: عندما يتوقف النظام عند حالة LOCKED، يجب أن تكتب "موافق" أو تعطيه ملاحظاتك ليكمل.
  • التعديلات المعمارية: إذا أردت تغيير شيء في هيكل البيانات، اطلب منه تحديث architecture.md أولاً، وليس تعديل الكود مباشرة.
  • ذاكرة المشروع: النظام يخزن أسباب اختيار التقنيات في project/context فلا تقم بحذف هذا المجلد أبداً.

💬 ردود سريعة للـ Gates

موافق، أكمل المرحلة التالية.
الـ Domain Model ممتاز، لكن أريد إضافة كيان...
أرفض المخاطر. قم بتعديل المعمارية...
